# 企业服务部署与管理

这是一个企业内的集中服务，Windows 工作台按岗位连接。PostgreSQL 保存账号、业务、流程版本、审批和执行租约；文件卷保留原件、DSH 执行目录和恢复前快照。AI 统一通过锁定的官方 DSH SDK 执行。关闭工作台不会停止服务器上的任务。

## 部署

目标是 Linux x64、Docker Engine 与 Compose v2。首次构建需要联网获取锁定依赖和容器基础镜像，建议预留 8 GB 内存及充足磁盘。当前开发机没有 Docker，镜像构建、Linux 部署及容量指标尚未实测。交付的是可构建部署源码包，不是已验证的离线镜像包。

1. 解压企业部署源码包。不要把旧版 Windows 安装包当作服务器。
2. 在有 Node.js 24 的部署准备电脑运行 `node scripts/configure-enterprise.mjs`，生成 `.env`；也可在临时 Node 容器中运行此脚本。生成器不覆盖已有文件。妥善保管加密密钥，丢失后无法解密模型凭据。
3. 修改 `.env` 的 `ENTERPRISE_DOMAIN`，把内网域名解析到服务端 IP。其余三个随机值分别是数据库密码、32 字节加密密钥和首次管理员初始化代码。密码只使用生成的十六进制值，避免连接字符串转义问题。
4. 在部署目录运行 `docker compose config` 检查配置，再运行 `docker compose up -d --build`。查看 `docker compose logs --tail=100 enterprise` 和健康状态。数据库没有映射到主机端口。
5. 默认 Caddy 使用内部 CA。执行 `docker compose cp gateway:/data/caddy/pki/authorities/local/root.crt ./enterprise-root.crt`，由企业管理员确认指纹后，在各 Windows 电脑的受信任根证书颁发机构中安装该证书。不要关闭证书校验。企业已有受信任证书时，由管理员替换网关证书配置。
6. 安装新版 Windows 客户端，填写 `https://你的内网域名`，点击连接服务器，输入初始化代码创建第一个管理员。密码至少 12 字。后续启动只需账号密码，登录会话有效期 8 小时；服务地址保存在本机，登录令牌只在宿主内存中保留。

不要把示例测试服务 `enterprise/tests/test-service.ts` 用于部署。它使用测试数据库、公开的测试账号和明确标记的测试模型，生产入口不会加载它。

## 组织与权限

先在管理与设置中创建部门，设置上级部门；再建立员工账号。内置管理员、项目经理、执行人员、验收人员四种角色，可给账号组合分配角色。本版不提供自定义角色定义器。最后一个管理员不可停用。管理员重置密码或停用账号会撤销该账号已有会话。

业务权限由服务端校验，不依靠隐藏按钮。部门记录按部门及项目成员范围读取；节点按指定人员或责任岗位和部门办理。转办目标必须符合岗位及部门要求。管理员负责跨部门流程设计和配置授权资料，项目经理维护本部门项目、组件和流程。

## 样板、组件与流程

点击“安装／重置项目交付样板草稿”创建样板部门、三类岗位组件、五个 AI 岗位卡和项目交付流程。此操作重置同名样板草稿，不会改写已发布版本。建议先创建组织和账号，再调整样板部门及节点责任人。

组件配置包括岗位职责、输入表单、输出交付物、责任岗位、部门、AI 帮手和验收规则。上级组件表示业务层级。流程以节点和连线连接组件；当前成果按命名字段交接，并在人工办理页展示上游交付依据。尚无逐条字段映射表达式编辑器。

流程设计页可以配置开始、AI、人工任务、人工审批、条件、并行、汇合、子流程和结束节点；点击流程图选择节点，在表单中配置连线。当前采用自动排布，不是拖拽画布。保存草稿允许未完成的配置；发布时检查图结构、人员、组件和子流程版本。已运行实例绑定发布快照，后改草稿不影响旧实例。子流程绑定发布时的具体版本。

完整样板：需求受理 → AI 拆计划 → 经理审批 → 两项并行岗位执行 → 汇合 → AI 质检 → 条件判断（不合格时人工处理）→ 人工验收 → AI 复盘 → 归档。验收退回指定的并行执行阶段，新一轮保留旧成果和审核历史。归档后经理可以创建关联本次复盘的改进任务。

## AI 配置与考核

管理员先在模型服务中配置兼容 OpenAI Chat Completions 的服务地址、模型名称和密钥，再在各数字员工岗位卡中选择模型。服务端密钥使用 AES-256-GCM 加密保存；不返回客户端、不进入业务导出。默认仅允许 HTTPS，localhost 仅用于本机测试。内部 HTTP 模型网关如确有需要，应由部署管理员显式设置 `ALLOW_INSECURE_MODEL_HTTP=1`，并保护内网链路。

岗位卡维护技能文本、职责与限制、所选资料、成果要求、转人工条件、见习／持证运营阶段及考核标准。这些配置是约束和记录，不表示获得任何专业认证。Bad Case 在“不满意案例与改进”登记并追踪。质量判断需要按企业验收标准人工确认。

AI 只接收授权资料正文和流程上下文；系统、文件、网络和委派工具全部被执行边界插件拦截。没有对 AI 开放数据库。成果必须通过结构检查，正式审批只能由人工接口办理。当前执行适配采用“给定上下文 → 结构化结果”模式，不支持任意外部业务工具。未配置模型时仍可管理和设计；AI 节点会显示配置错误，配置后由经理核实并重试。

试运行使用同一 DSH SDK 和真实配置的模型，产生独立流程实例。自动化测试模型不会进入生产入口。没有真实模型凭据时，不能把自动化通过当作 AI 业务验收。模型连接可通过岗位“试运行”核实。

## 异常与恢复

运行页展示节点状态、尝试次数、DSH 会话标识、成果和错误。失败后人工重试；租约过期的中断调用标记“结果待核实”，明确确认后才重试，不自动重复未知调用。取消父流程会取消未结束子流程。并行分支未汇合前不进入后续质检；AI 完成不会代替人工审批。

请在异常时先检查服务网络、模型凭据和日志，再重试。客户端断网保留服务端待办并重连；重启客户端需要重新登录。当前没有离线写入队列，企业业务办理需要连接服务器。个人 DSH 对话入口继续保留。

## 资料和迁移

资料支持 TXT、Markdown、DOCX、文字型 PDF；最大 10 MB。保留原始文件、校验值、正文、版本、部门可见范围和项目关联。扫描 PDF 提示需要 OCR，本版不识别。岗位卡显式选择资料，模型上下文保留资料 ID 和名称。任务可关联资料，流程报告导出 DOCX，任务列表导出 CSV。

旧版迁移：管理员在原来有本机 SQLite 的电脑登录 → 管理与设置 → 旧版迁移 → 预览 → 映射原负责人到企业账号 → 选择部门 → 确认。不会自动上传或覆盖原 SQLite，同一备份不能重复导入。旧版只有文字正文的资料标记为无原件，需要补传。旧草稿／审核历史保留在迁移归档记录中；不会自动转成新流程实例。旧 DSH 会话仍属于原客户端，不搬成服务端会话。

## 备份、升级和恢复

工作台“业务备份”包含业务记录、原始附件、流程版本及实例；不含账号、密码、模型凭据和 DSH 会话，恢复请求上限 64 MB。较大数据与灾难恢复使用完整运维备份。业务恢复会替换业务记录，要求没有运行中的流程；恢复前自动保存记录快照并保留原件。跨企业或全新账号体系需要另行重新映射负责人，本版业务恢复用于同一企业。

在部署目录运行 `sh enterprise/backup.sh /安全路径/新备份目录`。脚本停止企业执行和网关，使用 pg_dump 备份数据库，打包企业文件卷和内部证书卷，并保留 `.env`，结束后恢复服务。完整备份含凭据，必须加密保管并限制访问。脚本尚未在 Linux Docker 环境实跑。

完整恢复应在维护窗口和隔离测试环境先演练：

1. 核对备份校验值和源码版本，保存现有完整备份；停止企业服务及网关。
2. 使用原 `.env`（尤其原加密密钥）和同版 Compose；启动数据库，使用 `docker compose exec -T database pg_restore -U enterprise -d enterprise --clean --if-exists --exit-on-error < /备份/database.dump` 恢复。
3. 通过 `docker compose run --rm --no-deps --entrypoint tar enterprise -C /data -xzf - < /备份/enterprise-data.tar.gz` 恢复企业卷；同样用 gateway 容器恢复其 `/data`。覆盖前检查目标卷正确，保留原备份。恢复的是已有命名卷，不要执行 `down -v`。
4. 启动服务后核查账号、附件、流程待办。恢复到运行中的 AI 调用会在租约到期后标记结果未知，应人工核实。

升级前做完整备份，再部署同一源包中的服务器与客户端。客户端检查 API 版本为 2，旧服务不会被当作兼容服务。客户端覆盖安装保留用户数据；首版手动升级，未接官方更新渠道。
